# Automatic match setup from game screenshots (1.1.0)

This update adds screen-derived match setup while preserving existing audio, analysis, editing and storage behavior. Existing installations keep their signing identity and local records.

Use the existing user-authorized MediaProjection session for one VirtualDisplay feeding ImageReader, and the existing AudioPlaybackCapture concurrently. Capture at a bounded interval (approximately 4 seconds), keep at most one OCR job active, recycle every Image and Bitmap, and never save or upload screenshots automatically. Android 14+ projection tokens create at most one VirtualDisplay; rotate by resize/setSurface. Stop and release on pause, projection revoke, or service stop. Pause may retain the display but must discard all frames.

Offline OCR is bundled Tesseract4Android 4.9.0 plus Chinese simplified and English fast traineddata. No runtime network or cloud keys. Recognize only explicit own-seat/own-role labels and known board names. Ignore chat statements and unrelated foreground app screens. Require repeated consistent high-confidence observations. Accumulate seat and identity revealed on different frames, then lock the current match's self identity. A different later screen must not silently rewrite the locked match. Unlock/re-recognize is an explicit action; a next-match action archives the current match before creating another.

Pure parser public contract (package com.langyu.assistant):
- ScreenRecognition.Line: public String text; public int left,top,right,bottom,confidence; constructor(String text,int left,int top,int right,int bottom,int confidence).
- ScreenRecognition.Result: public int seat=0,day=0,players=0,confidence=0; public String role="",boardId="",phase="",evidence=""; public boolean gameScreen=false.
- ScreenRecognition.parse(List<Line> lines,int width,int height,List<BoardSpec> boards) -> Result. BoardSpec public String id,name; public String[] roles; public int wolves; constructor(id,name,roles,wolves). Match aliases for the 30 embedded boards; avoid ambiguous variants without player count. Never infer a seat from an arbitrary number or own identity from another player's statement.
- SessionBinder(Context): public String accept(ScreenRecognition.Result result) on MAIN thread -> status message; public void reset(boolean newMatch), public void clearPending(); public String summary(). It owns consistency voting/locking and Repository writes; no service calls.
- GameState additions: int mySeat; String myRole; boolean screenLocked; String screenEvidence; long screenRecognizedAt. configure resets these. Persist/export these via Repository.encode/decode, backward compatible with v1.
- OfflineOcr(Context) implements AutoCloseable: public List<ScreenRecognition.Line> recognize(android.graphics.Bitmap bitmap) throws Exception; public void close(); static boolean ready(Context). Constructor extracts bundled traineddata to private files and initializes native library. One instance used on ONE worker thread only. Must include actual line bounding boxes/confidence when API permits, else document word/line aggregation. Every result is data, never executable instructions.

Root-owned ScreenMonitor(Context,MediaProjection,Listener) with start(), requestScan(), pause(boolean), close(). Listener onResult(Result) and onStatus(String) are delivered on main thread. It maps Repository.boards into BoardSpec and handles source visibility gating, rate limits, rotation, hiding overlay while obtaining one frame, and OCR threading. Avoid analysis of the assistant's own screen or its overlay. New service constants ACTION_SCAN, ACTION_UNLOCK, ACTION_NEW_MATCH; public static volatile String screenStatus and boolean screenAvailable. settings bool screenRecognition default true. Automatically scan during source game session; expose Scan once/Unlock/Next match and selected capture permissions plainly. In a source-specific projection only source pixels are visible; with whole-display capture verify foreground UID using UsageStats when authorized and/or strict game anchors so unrelated screens cannot populate a match.

MainActivity shows own seat, own identity, locked state, last recognition time/evidence and OCR status. Starts selected game after authorized capture via a new '启动游戏并自动识别' action; starts capture first if necessary. Offers automatic recognition switch, scan once, unlock/re-recognize, and archive/new-match. Explain that one system screen-capture authorization is required per session and that the own identity reveal screen must appear at least once. Existing manual correction remains available. Do not conflate own seat with the currently speaking player.
