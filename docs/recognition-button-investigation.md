# “识别本局”无反应：排查与修复范围

## 现场观察

1.1.0 的一个 Android 16 vivo 实例中，捕获前台服务和投屏会话存在，录音、悬浮窗及使用情况访问均已授权。将已打开的游戏切回前台后，悬浮窗持续显示“等待游戏画面；黑屏或受保护内容无法读取”。这说明流程没有得到可送入 OCR 的新图像，不能解释为“识别到了画面但身份置信度不足”。现场为游戏大厅，未取得真实对局身份牌验证结果。

旧版日志没有图像回调和时间戳诊断，因此目前不能进一步区分系统没有交付图像、图像交付延迟、会话选区问题或时间戳过滤。不能据此断言 vivo 禁止截图，也不能把静态修复当成实机已经恢复。

按最新要求暂停真机验证后，后续工作仅涉及源码、离线测试、构建与包体检查。

## 已确认代码缺陷

- `ACTION_SCAN` 只设置排队标记，没有即时反馈。原状态未变化时，用户无法知道按钮是否收到点击。
- 前台事件查询初始仅回看 60 秒，并按当前时钟推进查询下界。已经在前台超过一分钟的游戏、延迟发布的前台事件，都能被永久漏掉。纯 Java 行为测试复现旧策略失败。
- 悬浮草稿保留输入焦点时会拒绝截图，点击识别却没有退出编辑，也没有说明拒绝原因。
- 截图等待时长很短，失败后没有正常重建授权会话的入口；界面把采集失败与内容保护合为一条提示，缺乏可操作的恢复方式。

## 1.1.1 修改

- 每次点击立即反馈；暂停、排队、编辑及结果过期均显示原因，保留现有的来源与对局隔离检查。
- 改用有界 24 小时启动/恢复历史、10 秒重叠窗口、事件时间排序去重和 Activity 匹配。空查询不再按当前时间推进游标；其它应用、锁屏及休眠仍不能被认作选定游戏前台。
- 手动识别先保存草稿并退出键盘编辑。
- 允许有界等待实际图像，记录图像回调、读取次数与时间戳诊断，不记录截图内容或语音文本。
- 增加“重新授权截图”：停止旧捕获，获取新的系统授权与服务。Android 14+ 的截图识别模式使用系统公开的默认屏幕捕获配置，仍需系统明确授权。
- 补齐新 ImageReader 的监听，停止等待回调在 Activity 销毁时取消。

## 验证与剩余限制

本次完成 253 项原有核心断言、182 项截图解析断言、40 项前台追踪断言，以及 APK 构建、签名、模型和四种 ABI 包体检查。前台追踪测试先用旧策略观察失败，再确认修复后通过。

这些结果证明已确认的代码缺陷及构建检查得到处理，不能证明 vivo 的真实截图采集已经恢复。下一次实机验证应先确认点击反馈、实际图像回调与读取，再展示本人身份牌核对解析。应用不能从未显示的本人身份或受保护图像中确定身份。
